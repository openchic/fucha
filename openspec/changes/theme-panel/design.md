## Context

依赖 change 2 的 ThemeToken 契约、generateCss 单源管线与预览宿主。对应里程碑 M2。存储沿用既定决策：不引 electron-store，userData 下 JSON 文件 fs 读写。

## Goals / Non-Goals

**Goals:**

- 面板逐项调 token，实时反映，另存自定义主题
- 自定义主题与偏好的文件持久化（改名、删、导入导出）
- deriveToken 自动建议（取主色 + 选预设，可见可改可还原）

**Non-Goals:**

- 多预设库扩充、主题分享
- 从源站学排版（已明确不做）
- 取色器 / 滑杆以外的编辑交互形式

## Decisions

机制、token 契约与存储布局以 docs/DESIGN.md 的「主题系统」「缓存与存储」为准，本文只保留本 change 特有的取舍：

**面板状态走会话草稿 + 显式另存。** 自动保存会直接污染已存主题，恢复成本高，否。

**存储布局目录即主题。** 便于整目录导出与未来扩展元信息；单文件聚合会让重命名与删除变成全量重写，否。

**入口跟随行为，面板占据元信息区域。** 主题入口留在顶部命令栏，编辑面板替换正文上方的元信息带；悬浮抽屉会遮住预览，实时反馈闭环会断，否。

**滑杆范围直接取 token 契约的字段边界。** 面板不另立一套边界，避免调得出但校验不过。

**deriveToken 纯函数，输入 Article 元信息与内容特征。** 主色由 cover（og:image）或 favicon 缩采样后量化聚类取主簇，转 HSL 做饱和度与明度归一（品牌色直接当主色常常过艳）；内容特征按代码块与表格密度映射预设；输出 `Partial<ThemeToken>` 只含颜色族，排版不输出。primary 同时驱动标题装饰与引用边条，不维护派生颜色副本。建议条在面板顶部，显示主色块与来源预设，带应用按钮；原主题 id 不变，可一键还原。对比度校验用 WCAG，自实现约二十行，不引库。

**取色器自绘触发按钮，弹层用原生。** 滑杆用原生 range 加样式；完整自绘取色器工程量与收益不成比，推迟。

## Risks / Trade-offs

- [cover 图跨域 canvas 取色被污染] → 优先走主进程下载后读文件字节，渲染进程不碰跨域 canvas
- [聚类对渐变 logo 取出色偏] → 取主簇的同时算色相方差，方差过大回落 favicon 或默认色
- [用户手动改 preferences.json 损坏] → 读失败回默认预设，不阻断启动
- [自定义主题增多后面板列表过长] → M2 不做搜索分组，列表溢出滚动，够用
