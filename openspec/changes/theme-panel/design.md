## Context

依赖 `local-store` 的 SQLite 底座与 M1 的预览/导出管线。M1 的 `generateCss(token)` 是单一生成器，只能表达 token 字段；M2 要让主题拥有自己的 CSS，同时让用户只调 token。核心取舍是把「稳定接口」和「主题实现」分开。

## Goals / Non-Goals

**Goals:**

- token 可调、主题可保存、自定义主题可原地编辑并同步引用文章
- 内置主题只读；另存为与完全自定义新建走独立设置页
- 预览与导出一致，导出仍能落到微信可内联的样式
- 主题包可导入导出，失败时整包拒绝
- 内置主题可扩展，旧 id 不因升级换样

**Non-Goals:**

- token 自动生成与取色
- 应用内 CSS 编辑器
- 历史侧栏与批量主题迁移
- 每个元素的四边盒模型 token

## Decisions

**自定义主题原地编辑，同步所有引用文章。** 编辑不再生成版本：`updateTheme` 更新同一主题的 token/css，引用它的文章在下次渲染时换样；另存为和完全自定义新建才创建新主题。代价是编辑当前主题会改变历史文章样式，这是明确选择的行为，不引入主题版本或文章级快照。内置主题只读，不能原地编辑。

**主题管理放在独立设置页。** 主题选择留在文章信息带下拉；下拉只列主题名称与当前值，底部进入 `/settings/themes` 作为主题管理入口，历史栏右下角也提供设置图标。设置页是 Home 的兄弟布局，左侧设置导航、右侧主题列表与配置页；原来的 ThemeManager 弹窗和内联 ThemePanel 移除。

**配置页用固定示例文章预览。** 配置页左侧用内置示例文章实时展示草稿效果，右侧是 token 控件；不读取当前文章、不做跨页同步。保存后返回文章时 Preview 重新挂载并加载已落库主题，避免在设置页和文章页之间维护两份预览状态。

手机画布上方固定显示「示例」。正文使用王勃[《滕王阁序》](https://zh.wikisource.org/zh-hans/滕王阁序)节选，分节标题和读序札记为示例编排。札记用字词表、摘句代码和注释展示排版元素，江天示意图沿用图片与图注样式。天空和江水都带浅暖黄，水面略深。落日旁的薄云和橙粉霞光轻轻融入天色，江面在同一方向略泛暖色。远山分列两侧，中间留出开阔的水天交界。正文沿用文章预览的 DOM 归一流程，三列表格可在窄屏局部横滚。

**token + theme.css 两层。** 把所有元素盒模型都 token 化会让接口膨胀，且很多控件在部分主题上无效；token 只保留约 20 个跨主题稳定字段，逐元素 margin/padding/border 放 theme.css。应用维护 base.css，主题只写差异；字族、页面底色等根级表现用单独成条的 `&` 规则写在 theme.css，避免枚举正文标签。

**变量路径与具体值路径共用同一份 CSS。** 预览把 token 写成 `.article-body` 上的 CSS 变量并注入 base + theme；导出把同一份 CSS 的 `var(--fucha-*)` 替换成具体值，再交给 juice。juice 不解析变量，因此导出前必须清零 `var()`。

**CSS 校验 fail-closed。** 主题包来自外部，CSS 注入风险与微信兼容风险都必须挡在导入时。只允许元素/类/后代选择器与共享的微信属性白名单，拒绝伪类、`@` 规则、`!important`、`url()`、契约外变量与 `<>`，错误带行号；任何一条失败整包拒绝。

**标题六级同形并直接挂 token 顶层。** 旧模型 h1–h3 共用排版、h4–h6 回落正文，用户要求六级都能各自调整；外层 `heading` 包装不再提供额外语义，去掉。

**书卷的正文一级标题与二级标题同样式。** 公众号文章标题由平台单独设置。书卷正文的 H1 与 H2 都使用 20px、600 字重、1.4 行高、左对齐、无装饰，以及 28px 上边距和 14px 下边距。正文分割线沿用原色和宽度，改为实线。

**书卷用字号和间距区分标题。** 六级标题都用 600 字重，避免低级标题比主要小节更粗。H5 用 14px 字号和 18px 上边距，H6 用 13px 字号和 16px 上边距。正文上内边距从 40px 调为 32px。

**共享正文样式处理标题内的粗体和图注间距。** 标题中的 `strong` 和 `b` 继承标题字重与颜色，防止公共粗体样式把书卷标题显示为 700。图注紧跟图片时，由图注提供 8px 的间隔，图下边距放在图注后。预览保留的图片链接与导出解包后的图片都匹配此规则。

**内置主题版本化。** 内置主题不写入数据库；升级视觉时新增 id，旧 id 保留，避免历史文章换样。当前提供 `default`、`shujuan` 与 `danxia`，`shujuan` 用 theme.css 的 `&` 根规则选择衬线字族，并收细引用边条、收紧图注字距，`danxia` 只靠 token 表达暖橙主色、灰底与标题竖条。

**主题包用 stored zip，不引第三方库。** 包内只有两个文本文件，压缩收益为零；主进程直接写/读 zip，读取支持 stored 与 deflate，拒绝加密、zip64、路径穿越与超出大小上限的条目。导出时不压缩；导入时只接受 `theme.json` 与 `theme.css` 两个文件。

**代码语法主题限定三套内置色板。** 代码 tab 提供语法主题下拉和可选的代码块背景：`hljsTheme` 只接受 `github` / `atom-one-light` / `xcode`；`code.backgroundColor` 缺省未设置、跟随语法主题；色块直接显示当前值，未设置时显示语法主题的默认背景色，重置回到保存值（保存值未设置即回到跟随）；未知值拒绝。语法主题决定语法色与缺省代码块背景，`code.backgroundColor` 可覆盖；`quote.backgroundColor` 用于引用，行内代码使用 `code.inlineBackgroundColor`，表头由 `table.headerBackgroundColor` 控制；自定义 `theme.css` 可以覆盖 `pre` 与 `th` 背景及 `.hljs` 颜色。示例预览会先跑语法高亮，保证切换语法主题时可见。

**配置页采用手机视口预览加固定检查器。** 左侧示例预览用设备下拉切换常用逻辑尺寸：iPhone 18 Pro 402×874、iPhone 16 393×852、iPhone SE 375×667、Pixel 7 412×915、Galaxy S21 360×800；预览框宽高取所选设备并受窗口可用空间限制（默认 iPhone 18 Pro），窗口高度不足、预览框撑满可用区时，标题与预览框、预览框与预览区底部的留白相等；窗口更高时预览框保持顶部对齐（距标题留白不变），余量留在下方，不垂直居中；水平居中；文章在手机视口内滚动。切换设备时预览框宽高以 200ms ease-out 过渡，系统开启减少动态效果时直接切换。右侧是 340–400px 的检查器，颜色/排版/代码/页面四组控件用 tab 切换；排版内按正文、标题、引用、表格、图片、分割线分段；标题含字号、字重、行高与上/下边距，引用含字号、上下/左右内距与圆角，图片含上/下边距与圆角，分割线含上/下边距与样式；代码 tab 分代码块与行内代码两段，代码块含语法主题、背景色、字号、上下内距、左右内距、行高与圆角，行内代码含圆角；颜色 tab 分基础、背景、线条三段；页面 tab 提供上、右、下、左四个内边距；分组标题下用 1px 分割线，分组内行距 12px、分组间距 24px；控件纵向铺开，每行名称在左、控件在右；数值用可输入数值与步进控件（单个圆角边框组，焦点落在整组），选项用下拉。字号层级按分组区分：四个 tab 的分组标题 14px ink，字段标签与右侧控件文字 12px ink；单位、说明与未设置提示 12px ink-soft。下拉选中值同样用 ink，不读成次要文字。编辑页顶部工具栏放返回、标题与保存状态；右侧检查器顶部放主题名称，取消/保存固定在检查器底部，中间从 tab 开始；另存为从主题列表操作。

**次级字号只作用于图注与上下标。** 行内代码与表格按正文 0.875 倍缩放，跟随 `text.fontSize` 变化；代码块与引用使用独立字号，分别由 `code.fontSize` 与 `quote.fontSize` 控制；`次级字号` 控件只调整图注、`sup` 与 `sub`，避免用户误以为它还控制行内代码与表格。

**引用背景色、行内代码背景色与表头背景色独立配置。** 颜色 tab 分别配置 `quote.backgroundColor`（引用）、`code.inlineBackgroundColor`（行内代码）与 `table.headerBackgroundColor`（表头），三者相互独立。

**正文色与标题色拆开配置。** 颜色 tab 分别配置 `text.color` 与 `headingColor`；标题统一使用 `headingColor`。

**边框色与分割线色拆开配置。** `borderColor` 控制表格与代码块边框，新增 `divider.borderTopColor` 控制分割线。书卷的表格使用浅暖灰色 `#ece5db`。代码块的 `code.borderStyle` 设为 `none`，用与引用一致的浅纸色 `#faf7f2` 区分代码块和白底正文。

**单字段重置只回退到打开时的保存值。** 每个控件比对 `baseline` 与当前草稿，偏离时在控件左侧显示重置图标，点击只恢复该字段；代码块背景使用同一颜色控件，未设置时色块显示语法主题的默认背景色，重置同样回到保存值（保存值未设置即回到跟随）。示例样张补行内代码与 H₂O / x² 上下标，让块底色与次级字号都有可见消费者。

**数值控件用输入加步进，不用滑杆。** 每行显示当前值、单位与 −/+ 步进；点击数值直接键入，Enter 或失焦提交，Esc 取消；步进与 ↑/↓ 即时更新预览，手输在提交时生效；提交按 token 范围与步长归整，越界夹紧，到达端点时对应步进按钮禁用。此前每个数值占一条整宽滑杆，13 条轨道让检查器视觉过载，且小范围数值很难拖到精确值；改为数值行后一屏可读的字段更多，精确值也可直接键入。

**色值弹层与对比度提示。** 颜色行不常驻显示色值，色块悬停立即显示当前色值气泡，点击打开取色弹层；弹层用 `@uiw/react-color` 的 Sketch，关闭 alpha，去掉组件自带背景与阴影，保留项目白底弹层；Hex/RGB 字段可输入或粘贴，非法值不写入。正文色与标题色对白底、引用背景色、行内代码背景色、表头背景色，次级文字色对白底按 4.5:1 计算，低于阈值时占用该行说明位显示最低的一对与具体比值，只替换说明文字、不增加行高，避免列表跳动，也不阻止保存；装饰色与代码语法色不参与。颜色和数值控件的说明通过 `aria-describedby` 关联到输入。

**主题管理入口不再放在下拉的动作区。** 下拉的动作区只保留一个「主题管理」入口，避免把选择和编辑混在同一层；具体的新建、编辑（含改名）、另存为、导出、删除在设置页完成。

## Risks / Trade-offs

- [主题 CSS 破坏微信兼容性] → 属性白名单与选择器限制在导入时拦截；运行时不静默修正
- [内置主题不断累积] → 旧 id 只修 bug、不改样式；数量增长后加 deprecated 标记，删除需先迁移历史文章
- [原地编辑改变历史文章样张] → 列表页明确提示修改会同步到引用文章；想保留旧样式时用「另存为」创建新主题
- [被文章引用的主题无法删除] → 拒绝删除并提示引用数量；v1 不做批量迁移
- [主题包 id 冲突] → 导入直接拒绝，要求换 id 后重试
- [CSS 校验覆盖不全] → v1 限定最小选择器与属性集合；规则扩展必须同时更新 base/export 允许列表与 harness

## Migration Plan

- schema v8 无新增字段：`themes` 的 `css`、`token_version`、`source_theme_id` 已存在；只新增 `updateTheme` 领域方法与 IPC，不新增表或版本。
- 已有自定义主题行保持原 id；从本次起可原地编辑，引用文章同步换样。
- 回滚：代码回退后已有主题仍可读取；编辑过的主题内容保留，不需要数据迁移。
