## Context

绿地项目，electron-vite 脚手架已就位（main / preload / renderer 三进程骨架，窗口、安全基线与应用壳配色已按设计就位），架构边界见 docs/DESIGN.md。本 change 对应里程碑 M0。

## Goals / Non-Goals

**Goals:**

- 打通"输入链接 → 抓取 → 提取 → 净化 → 只读预览"主链路
- 落定跨进程数据契约（Article / ImageAsset）与 IPC 面
- 微信公众号文章可用（data-src 取图、Referer 下载、验证码抛错）
- 二十个不同类型链接的提取正确率验证

**Non-Goals:**

- 主题系统、内联导出、剪贴板（change 2）
- 隐藏 BrowserWindow 二级兜底、通用站点适配系统
- 正文编辑、图片重试退避、素材库

## Decisions

### Apple 风格显示与交互优化

沿用单一白色画布、676px 正文和系统字体，不引入组件库。应用壳的文字与线条改用中性灰，近黑绿主按钮与少量鼠尾草绿标记保留。初始态用帆形线性字标、32px 品牌、16px 说明和 56px 链接字段建立层次；文章信息带先放「首页」操作，再以 26px 完整宽度呈现标题，元信息降为次级文字，长标题不与按钮争抢宽度。错误原因与重试动作相邻；静态骨架不闪动，并尊重减少动态效果。

链接字段提供清除按钮及内联错误，允许省略协议的有效域名并补全 HTTPS；无效地址、非 HTTP(S) 协议、带账户密码的 URL 或包含空白的地址不发起抓取。Cmd/Ctrl+L 在初始态选中链接字段。加载取消保留已提交链接并返回输入态，通过递增请求标识忽略晚到的抓取或图片结果，不宣称取消底层网络传输。

图片状态的已确认问题是存在 failed 图片时界面仍显示「正在下载」。根因是原显示逻辑只比较 done 与总数；现在依据 pending、done、failed 分别给出下载中、全部就绪或成功/失败数量。按后续界面精简要求，元信息带不再渲染任何图片状态或数量，也不保留占位；三态仍由下载管道内部维护。IPC Promise 拒绝也进入可重试错误态，避免停留在加载屏。

机制与常量以 docs/DESIGN.md 的「架构」「抓取」「提取与净化」「图片」「界面」为准，本文只保留本 change 当时的取舍：

**本地图片用自定义协议，不把字节经 IPC 传成 blob URL。** 每张图一次跨进程拷贝且需放行 `blob:`，否。

**抓取放主进程，用原生 fetch。** 渲染进程受同源策略限制；Electron `net` 能力等价但类型与测试不如原生 fetch 直接。

**提取与净化放渲染进程。** 自带 DOM；主进程 jsdom 多一份 DOM 实现与内存，否。

**契约集中在 src/shared/types.ts。** 分散定义有漂移风险，否。

**微信适配用最小域名表。** 现阶段无第二个站点证明通用配置系统的形状，等真实需求出现再泛化。

**界面用单一状态机，不引路由。** 阶段推进在渲染侧，无需 IPC 事件绕一圈；独立加载页会闪跳，否。

**应用壳用 Tailwind v4 与 @theme，不引组件库。** 组件库的视觉基因与基调相逆，每处都要覆盖默认样式。

**视觉优化只调整层级与比例，不换品牌色或引入装饰。** 初始品牌字标放大并取消宽字距，正文与表单保持同一测宽；预览标题与元信息拉开层级，次要按钮使用中性底色，错误原因使用浅底色块；内容区使用单一白色背景，去掉外圈留白、背景分层与外边框。输入框聚焦仍只用同色细描边，文章正文样式继续独立于应用壳。窗口拖动统一由顶部触发，初始态使用顶部空白带，其余状态使用信息带，避免阅读区点击与文本选择被拖动行为截获。

**窗口拖动统一由顶部触发，初始态使用顶部空白带，其余状态使用信息带，避免阅读区点击与文本选择被拖动行为截获。预览与失败态的信息带提供「首页」，点击后递增请求标识、清空链接草稿并回到初始态，使已经发出的图片下载结果不能再更新离开的文章。**

**换链接不进信息带。** 原位展开的紧凑输入区要额外维护编辑草稿、焦点归还与 Esc 取消三件事，而「首页」回到初始态后同一个链接字段已经承担改链接；预览与失败态只留「首页」，少一份只服务于一次改址的界面状态。

**M0 预览用最小可读样式基线。** 目的是验证提取正确性，不是还原排版。应用壳不设独立顶部栏，品牌只在初始内容区出现；预览态把标题、来源与「首页」组织进文章信息带，文章操作等能力就绪后再加到同一操作区。正文区域只保留横向文章信息与阅读内容，元信息与正文共用内容宽度。不可用控件占位会把临时操作误读成主内容，也不进入预览。

**图片下载不阻塞预览。** 骨架屏只承担请求与解析；若把图片下载作为第三加载阶段，正文会被慢图阻塞，和图片与预览解耦的约束冲突。提取完成即进入预览，下载完成后原位更新图片；元信息不展示图片状态或数量。

**内嵌 SVG 走独立静态白名单，不用 DOMPurify 的完整 SVG 配置。** 完整配置仍包含外部 `image`、`use`、动画与过滤器等资源入口。实现只放行图形、文本、渐变、剪裁与标记，保留安全 presentation 属性和有限 style 声明；外链字形引用、外部 `url()` 与 `href` 在属性钩子中移除，HTML 的 style 仍整体剥离。Readability 会删除全文 `<style>` 与 class，因此页面级及 SVG 内部规则必须在 Readability 前解析，只把安全声明内联到对应元素。合并时保留原内联样式的同名属性，同时保留由样式表计算出的其他属性；整段覆盖原 `style` 会再次抹掉 `fill`，D2 这类元素自带 `stroke-width` 内联样式的图形会大面积转黑。

## Risks / Trade-offs

- [本地图片合法请求曾无法读取] → 根因是路径解析把缓存目录误作第二段相对路径，且协议层经 `net.fetch(file://)` 读取失败；以缓存目录为首段基准解析并直接读取文件字节，用合法取图与路径穿越两类测试锁定
- [SVG 图片曾被存成 JPEG] → 下载端类型映射与 URL 兜底漏了 SVG，字节被命名为 `.jpg` 并以 `image/jpeg` 返回；两处同时补 SVG，并以扩展名与内容类型测试锁定
- [内嵌 SVG 的 rect 曾显示默认黑色] → 颜色写在 SVG 内部 `<style>`/class，而 Readability 会先清理两者；起初恢复原内联样式时整段覆盖又抹掉了已计算的 fill。最终按属性合并并移除样式源码，以 D2 图和实际计算色测试锁定
- [并发下载后缓存索引丢失映射导致重复下载] → 多个 worker 各自读改写 `index.json` 会互相覆盖；索引更新经模块级队列串行执行，二次提交以零新增图片请求验证
- [微信图片带 Referer 仍可能失败] → status=failed 加占位展示，预览不阻断
- [Readability 对部分站点提取错位] → 二十链接验证清单先行，bad case 沉淀进 profiles 域名表
- [源页面嵌入 iframe 或大图拖慢渲染] → 净化白名单移除 iframe，下载限并发加超时
- [验证码特征误判] → 特征识别宁窄勿宽，误判走通用错误路径，不误伤正常文章
