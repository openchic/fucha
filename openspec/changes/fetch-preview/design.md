## Context

绿地项目，electron-vite 脚手架已就位（main / preload / renderer 三进程骨架，窗口、安全基线与应用壳配色已按设计就位），架构边界见 docs/DESIGN.md。本 change 对应里程碑 M0。

## Goals / Non-Goals

**Goals:**

- 打通"输入链接 → 抓取 → 提取 → 净化 → 只读预览"主链路
- 落定跨进程数据契约（Article / ImageAsset）与 IPC 面
- 微信公众号文章可用（data-src 取图、Referer 下载、验证码抛错）
- 二十个不同类型链接的提取正确率验证

**Non-Goals:**

- 主题系统、内联导出、剪贴板（change 2）
- 隐藏 BrowserWindow 二级兜底、通用站点适配系统
- 正文编辑、图片重试退避、素材库

## Decisions

### Apple 风格显示与交互优化

沿用单一白色画布、676px 正文和系统字体，不引入组件库。应用壳的文字与线条改用中性灰，主按钮与少量标记统一用鼠尾草绿，近黑绿 #2f3e33 已随主按钮改色一并去掉。初始态用帆形线性字标、32px 品牌、16px 说明和 56px 链接字段建立层次；「首页」固定在窗口左侧，文章信息带以 26px 完整宽度呈现标题，元信息降为次级文字，长标题不与按钮争抢宽度。错误原因与重试动作相邻；静态骨架不闪动，并尊重减少动态效果。

链接字段提供清除按钮及内联错误，允许省略协议的有效域名并补全 HTTPS；无效地址、非 HTTP(S) 协议、带账户密码的 URL 或包含空白的地址不发起抓取。加载取消保留已提交链接并返回输入态，通过递增请求标识忽略晚到的抓取或图片结果，不宣称取消底层网络传输。

图片状态的已确认问题是存在 failed 图片时界面仍显示「正在下载」。根因是原显示逻辑只比较 done 与总数；现在依据 pending、done、failed 分别给出下载中、全部就绪或成功/失败数量。按后续界面精简要求，元信息带不再渲染任何图片状态或数量，也不保留占位；三态仍由下载管道内部维护。IPC Promise 拒绝也进入可重试错误态，避免停留在加载屏。

机制与常量以 docs/DESIGN.md 的「架构」「抓取」「提取与净化」「图片」「界面」为准，本文只保留本 change 当时的取舍：

**本地图片用自定义协议，不把字节经 IPC 传成 blob URL。** 每张图一次跨进程拷贝且需放行 `blob:`，否。

**抓取放主进程，用原生 fetch。** 渲染进程受同源策略限制；Electron `net` 能力等价但类型与测试不如原生 fetch 直接。

**提取与净化放渲染进程。** 自带 DOM；主进程 jsdom 多一份 DOM 实现与内存，否。

**契约集中在 src/shared/types.ts。** 分散定义有漂移风险，否。

**微信适配用最小域名表。** 现阶段无第二个站点证明通用配置系统的形状，等真实需求出现再泛化。

**首页与预览拆两条路由，加载与失败留在预览页内。** 两屏的壳不同，首页整页滚动，预览是固定列，窗口拖动共用顶部 24px 空白带；路由让每屏持有自己的外壳，入口不再按状态判断。预览用 `?url=` 携带链接，刷新即重跑管线，取代此前用 sessionStorage 记住上次链接。用 Hash 路由，因为生产从 `file://` 加载，History 路由在刷新时会请求不存在的路径；加载与失败不单开路由，进入时就不会整页切换闪跳。

**应用壳用 Tailwind v4 与 @theme，不引组件库。** 组件库的视觉基因与基调相逆，每处都要覆盖默认样式。

**视觉优化只调整层级与比例，不换品牌色或引入装饰。** 初始品牌字标放大并取消宽字距，正文与表单保持同一测宽；预览标题与元信息拉开层级，次要按钮使用中性底色，错误原因使用浅底色块；内容区使用单一白色背景，去掉外圈留白、背景分层与外边框。输入框聚焦仍只用同色细描边，文章正文样式继续独立于应用壳。窗口拖动统一由应用壳顶部 24px 空白带触发，避免信息带和阅读区的点击与文本选择被拖动行为截获。

**窗口拖动限制在顶部 24px 空白带。** 用户反馈拖动区域过大，根因是整块信息带标记为 Electron 拖动区域，首页也单独铺设了 80px 高的拖动带。将拖动宿主统一移至 App 路由外的固定透明元素，高 24px，不参与文档流；各状态移除原拖动标记，普通内容恢复默认指针和文本选择行为。预览与失败态的页面壳在窗口左侧提供「首页」，点击后递增请求标识、清空链接草稿并回到初始态，使已经发出的图片下载结果不能再更新离开的文章。

**换链接不进信息带。** 原位展开的紧凑输入区要额外维护编辑草稿、焦点归还与 Esc 取消三件事，而「首页」回到初始态后同一个链接字段已经承担改链接；预览与失败态只留「首页」，少一份只服务于一次改址的界面状态。

**M0 预览用最小可读样式基线。** 目的是验证提取正确性，不是还原排版。应用壳不设独立顶部栏，品牌只在初始内容区出现；预览态将标题与来源组织进文章信息带，并将「首页」放在窗口左侧，文章操作等能力就绪后再加到同一操作区。正文区域只保留横向文章信息与阅读内容，元信息与正文共用内容宽度。不可用控件占位会把临时操作误读成主内容，也不进入预览。

**图片下载不阻塞预览。** 骨架屏只承担请求与解析；若把图片下载作为第三加载阶段，正文会被慢图阻塞，和图片与预览解耦的约束冲突。提取完成即进入预览，下载完成后原位更新图片；元信息不展示图片状态或数量。

**内嵌 SVG 走独立静态白名单，不用 DOMPurify 的完整 SVG 配置。** 完整配置仍包含外部 `image`、`use`、动画与过滤器等资源入口。实现只放行图形、文本、渐变、剪裁与标记，保留安全 presentation 属性和有限 style 声明；外链字形引用、外部 `url()` 与 `href` 在属性钩子中移除，HTML 的 style 仍整体剥离。Readability 会删除全文 `<style>` 与 class，因此页面级及 SVG 内部规则必须在 Readability 前解析，只把安全声明内联到对应元素。合并时保留原内联样式的同名属性，同时保留由样式表计算出的其他属性；整段覆盖原 `style` 会再次抹掉 `fill`，D2 这类元素自带 `stroke-width` 内联样式的图形会大面积转黑。

**SVG 中的纯文本标题在移除 `foreignObject` 前转为矢量文字。** 已确认的回归来自 D2 图表：标题「DeepSeek Harness」先在预览中消失，恢复后又变成通用粗体字体，标题线也与原图不一致。既有转换器过度要求容器及所有中间节点除标题外不含任何子元素，导致带空白装饰节点或安全行内标签的纯文本标题被跳过；净化器随后移除整个 `foreignObject`。转换器又只按容器高度估算字号并固定字重、线条颜色和宽度，丢弃来源 CSS 中的字体与边框。提取阶段现在只要求容器内恰有一个纯文本标题、其余节点没有可见文字；从标题及其祖先收集安全的字体和颜色声明，并从标题读取安全底边框样式后生成居中的 SVG 文字与线条。来源自定义字体仅在 SVG 实际引用且以受限 `data:` URL 内嵌时保留，CSP 据此允许 `font-src 'self' data:`；外部字体与源样式表仍被移除，其它可见内容也不会被保留。

**固定 SVG 多行文本的行坐标。** 已确认的回归来自 DeepSeek Harness D2 图表：节点多行文案以 `<tspan dy="18.5">` 表示第二行的相对基线偏移，经过提取序列化后仍依赖相对位移，导致预览中多行文字重叠；单纯放宽净化白名单仍无法稳定修复。对具有数值 `y` 且只含直接纯文本 `tspan` 子项的 SVG `text`，在净化前累积数值 `dy` 并将每行写成绝对 `y`；其余安全数值 `dx` / `dy` 只允许出现在 SVG `text` / `tspan` 上。

**微信正文容器先解除隐藏再提取。** 已确认的现象是三篇真实公众号文章预览只剩「原创…不喜欢」等页脚碎片。根因是 `#js_content` 以内联 `visibility: hidden` 隐藏，Readability 会跳过不可见节点。现在按 profiles 的 `revealSelectors` 在提取前清除该容器的 visibility 与 opacity，正文与图片清单恢复正常。

**微信图片按图片域名命中站点表。** 已确认的设计缺陷是下载侧用图片 URL 调用 `matchProfile`，而 `mmbiz.qpic.cn` 不在域名表里，Referer 实际从未发送。现在图片域名与文章域名共享请求头配置，三篇公众号的 34 张图片全部下载成功。

**相对地址以 finalUrl 归一。** 已确认的现象是 GitHub 文档 25 张图片在预览中全部裂图，根因是 DOMParser 的文档 base 仍是应用自身地址，Readability 把相对路径解析成 `localhost:5173`。提取前插入指向 finalUrl 的 base 元素，图片与链接都变成来源站点的绝对地址。

**文档站清理分为提取前与提取后两类选择器。** MDN 的基线条必须在 Readability 之后移除，因为提前删会改变正文候选，导致导语丢失；Node.js 的代码工具栏必须在提取前移除，因为 Readability 会把工具栏 `div` 改写成 `p`，提取后已无法按原选择器定位。profiles 因此增加 `dropSelectors` 与 `postDropSelectors`：前者直接删除，后者先标记 `data-fucha-chrome`，等 Readability 输出后再删。Josh Comeau 的 `data-demo-unit` 主 demo 用前者移除，未标记的交互插图保留为已知限制。

**引用块清除末尾段后距。** 截图中的公式引用块底部留白明显偏大。根因是正文段落通用的 `margin-bottom` 同时应用于引用块内部最后一个段落，并与引用块自身的 `padding-bottom` 累加。预览保留段落间距与引用块容器留白，但引用块最后一个直接子元素的段后距归零。

**用重新提取入口替换作者展示。** 文章作者仍由提取管线保存在 Article 中供来源记录与导出使用，预览信息带不显示作者；作者原位置改为中心无横线且带「重新提取」无障碍名称的刷新图标。点击后复用当前链接重跑抓取与提取，成功与失败分别回到预览态和既有错误态。

**重新提取保留现有预览。** 切回全页骨架会销毁正文滚动容器并造成明显跳动；预览内重试期间继续显示现有文章，只在按钮图标上提供旋转反馈并防止重复提交。提取成功后再原位替换内容；请求或解析失败时停下动画、保留旧文章并显示简短状态提示。初次加载和无可保留内容的错误重试仍使用原有加载态。

**刷新提示使用应用内锚定提示。** Electron 原生 `title` 提示由系统控制延时与消失时机，且刷新状态更新会替换提示文本，造成提示出现不稳定。刷新按钮改用绝对定位且不参与指针命中的应用内提示，通过同一容器的悬浮与键盘焦点状态控制显示，并跟随刷新状态更新文案。

**来源链接不显示下划线。** 元信息带保持链接可点击并在新窗口打开原始来源；去掉文本装饰，避免下划线与当前简洁的元信息样式不一致。

**加载态标题与取消操作同行。** 原布局用品牌文字占据标题行上方的操作栏，导致取消按钮与加载标题分离；将标题移入原操作行并移除品牌文字，阶段说明仍保留在下一行。

**预览头部收紧纵向间距。** 用户反馈预览头部占高过多，根因是三行内容叠加 36px 顶部留白、32px 操作行、18px 行下间距、12px 元信息上间距和 20px 底部留白。返回入口移至窗口左侧后，文章列顶部使用 60px 留白（原 24px 顶部、28px 操作行及 8px 行间距合并），元信息上方 8px、底部 12px；单行标题时总高约 146px，比原布局减少 38px。标题仍为 26px 并自然换行，来源、刷新入口和正文继续共用内容边界，不固定整个头部高度。

**加载切换与图片完成时保持预览稳定。** 用户反馈点击「生成预览」后，提取完成仍有界面跳动。加载态此前使用 36px 顶部留白与更大的标题、状态文字间距，预览态则使用 60px 顶部留白，导致标题切换时上下移动；同时图片下载完成会生成新的整篇正文 HTML，通过 `dangerouslySetInnerHTML` 替换所有文章节点。加载态因此与预览态统一为 60px 顶部、8px 标题与状态间距、12px 底部留白，骨架首行和正文首内容均从头部后 40px 开始；预览正文 HTML 在图片状态更新时保持不变，由已有文章节点按图片 ID 原位替换 `src`，不卸载正文或阅读容器。

**加载态头部改为更细的骨架行。** 用户希望标题和阶段提示区域也使用骨架屏，随后反馈标题灰条太粗。标题骨架可见高度收细到 12px，与正文灰条一致，并由 36.4px 的最小行高保留原标题布局；阶段行先保留原有高度，取消按钮位置与加载到预览的垂直起点不变，该高度在下一项对齐修正中调整为 28px；可见文案由骨架替代，但保留屏幕阅读器可读的标题和 `role="status"` 阶段播报。

**加载态阶段行与预览元信息行等高。** 复验发现加载切预览时仍有 5.6px 位移，来源是阶段行 22.4px、预览元信息行 28px（含 28px 刷新按钮）。阶段行改为 28px 后，加载态头部与预览头部同为 145.4px，正文骨架首行与预览正文首内容同为 185.4px；标题骨架仍为 12px 灰条，36.4px 行高与取消按钮位置不变。

**返回入口按窗口定位。** 用户希望返回按钮位于红绿灯下方的左侧空白区，因此将「首页」从 ArticleMeta 与 ErrorPanel 提升至 Preview 页面壳，预览和失败态共用。按钮顶部为 64px，箭头距窗口左边 24px，与顶部 24px 拖动带分离；按钮不参与文章列宽计算，也不随正文滚动。移除组件内原返回操作行，将其空间并入顶部留白（预览 60px、失败态 86px），保持现有标题与正文的垂直位置和头部高度。

## Risks / Trade-offs

- [本地图片合法请求曾无法读取] → 根因是路径解析把缓存目录误作第二段相对路径，且协议层经 `net.fetch(file://)` 读取失败；以缓存目录为首段基准解析并直接读取文件字节，用合法取图与路径穿越两类测试锁定
- [SVG 图片曾被存成 JPEG] → 下载端类型映射与 URL 兜底漏了 SVG，字节被命名为 `.jpg` 并以 `image/jpeg` 返回；两处同时补 SVG，并以扩展名与内容类型测试锁定
- [内嵌 SVG 的 rect 曾显示默认黑色] → 颜色写在 SVG 内部 `<style>`/class，而 Readability 会先清理两者；起初恢复原内联样式时整段覆盖又抹掉了已计算的 fill。最终按属性合并并移除样式源码，以 D2 图和实际计算色测试锁定
- [并发下载后缓存索引丢失映射导致重复下载] → 多个 worker 各自读改写 `index.json` 会互相覆盖；索引更新经模块级队列串行执行，二次提交以零新增图片请求验证
- [微信图片带 Referer 仍可能失败] → status=failed 加占位展示，预览不阻断
- [Readability 对部分站点提取错位] → 二十链接验证清单先行，bad case 沉淀进 profiles 域名表
- [源页面嵌入 iframe 或大图拖慢渲染] → 净化白名单移除 iframe，下载限并发加超时
- [验证码特征误判] → 特征识别宁窄勿宽，误判走通用错误路径，不误伤正常文章
